# AGENTS.md — правила для параллельных агентских сессий

## Карта владения файлами (во избежание конфликтов)

| Модуль | Путь | Агент может изменять |
| :--- | :--- | :--- |
| Боевое ядро | apps/game-client/src/game/ | только сцены и данные своей задачи |
| Контракты | packages/shared-types/ | только через отдельный PR type-sync |
| Инфраструктура | services/game-server/ | строго по своей задаче, без правок клиента |
| CRM | apps/admin-crm/, services/admin-core/ | без правок игровых сцен |
| ТЗ и docs | MASTER_ARCHITECTURE_SPEC.md, docs/ | ЗАПРЕЩЕНО изменять агентам |

## Общие правила
1. Одна сессия — одна ветка — один PR (лимит платформы Arena).
2. Перед стартом агент обязан сделать git pull от main.
3. Коммиты в формате conventional commits (feat/fix/chore/docs).
4. Ворота: `npm run typecheck`, `npm run build`, `npm test` — обязаны быть зелеными.
5. Ни один агент не пушит в main напрямую — только через PR.
6. Скрепка, формат 9:16 и запрет терминального UI — неизменные константы ТЗ.

## Лимит объёма сессии
- Целевой дифф одной сессии: до ~8000 строк. Превышение (как в случае 01a08e29 на 15 637 строк) — риск сбоя кнопки PR.
- Коммить маленькими атомарными кусками по ходу работы, не копи изменения к концу сессии.

## Именование веток
- Формат: `phaseN/task-slug` (пример: `phase1/fomo-wraith-ai`, `phase2/tgwa-auth`).

## Fallback при зависшей кнопке PR
Если кнопка создания PR недоступна, а ветка не запушена:
1. В чат агенту: «Закоммить все изменения и выполни git push origin <имя ветки>».
2. Если push не проходит: «Сохрани единый git diff относительно main в файл patches/<session-id>.patch и закоммить его в репозиторий».
3. PR создается вручную на GitHub либо следующей сессией поверх патча.

## Definition of Done для PR агента
- [ ] typecheck / build / test зелёные
- [ ] PR по шаблону .github/PULL_REQUEST_TEMPLATE.md
- [ ] Затронутые модули соответствуют карте владения
- [ ] Нет изменений в запретных файлах (ТЗ, docs, Скрепка, 9:16)
